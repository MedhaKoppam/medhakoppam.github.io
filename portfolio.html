Research design

Each session focuses on a particular AI concept. Students participate in one of three conditions: a non-game learning activity, the AI game being evaluated, or a control game that is not designed around the target AI concept.

After the activity, students are asked about their experience, including enjoyment, frustration, confusion, what they learned, and what they would change. Questions also go deeper into the game's experience and its learning objectives. Students then complete an assessment related to the concept.

The goal is to combine students' experiences and feedback with learning outcomes to understand how effectively the game supports learning.

Research questions

  • How engaging and enjoyable do students find the experience?
  • What aspects of the experience cause confusion or frustration?
  • What do students perceive themselves to have learned?
  • Which elements of the game support or hinder learning?
  • What changes do students recommend?
  • How does learning compare across the game, learning activity, and control conditions?

What I contribute

  • Support and facilitate playtesting sessions with students.
  • Observe interactions and document student feedback.
  • Engage students in post-activity questions about their experience and learning.
  • Help the research team understand patterns in student experiences during testing.
  • Contribute observations that can help evaluate and improve the educational games.

What I'm learning

This work is giving me hands-on experience with participant-facing research, structured playtesting, qualitative feedback collection, and the challenge of evaluating a product on two dimensions at once: whether people enjoy using it and whether it actually accomplishes its intended learning goal.

Designing Accessible Interactions for Complex Developer Tools

Exploring a more accessible way for users to interact with complex developer tooling by allowing them to express their intent in natural language and work with the resulting workflow through an interactive interface.

HCI Interaction Design Human-AI Interaction Developer Tools Software Engineering

The challenge

A powerful framework for large-scale code transformations required users to work directly with many abstractions, parameters, and workflow components, creating a barrier to entry.

The approach

We explored an interaction model where users could begin with their intent rather than first learning the underlying abstractions required to construct a workflow.

The challenge

A powerful framework for performing large-scale code transformations required users to work directly with a complex set of abstractions and configuration parameters. Creating a workflow required understanding how these components fit together before users could accomplish their actual task.

The problem wasn't the capability of the system — it was the interaction barrier between the user and that capability.

The approach

We explored a more accessible interaction model that allowed users to begin with their intent, rather than requiring them to understand the underlying abstractions.

The interface also supported an iterative interaction loop: users could generate a workflow, execute it, adjust runtime parameters, and continue chatting to refine the workflow or make changes. As part of the interface, we added direct-action UI elements within the chat experience that allowed developers to execute workflows and modify runtime parameters without leaving the conversation.

What I worked on

  • Developed the interface for presenting generated workflows.

Industry Projects · Microsoft Research

AI-Assisted Code Review & Testing in Git-Based Workflows

Designed and implemented Git-integrated interfaces that use AI to identify security vulnerabilities, suggest actionable fixes, and generate unit tests for code changes—while giving developers clear feedback and ways to verify the resulting changes.

HCI Developer Experience Human-AI Interaction Interaction Design Software Engineering

My role

Designed and implemented parts of the user-facing experience for AI-assisted code quality workflows, thinking about how developers encounter findings, understand them, take action, and verify the result.

Context

The work was developed through two hackathon projects and explored how AI-generated code analysis and changes could fit naturally into existing Git-based workflows.

Focus

Making AI-generated findings and changes transparent, actionable, and convincing to developers without requiring them to leave the workflow they already use.

01 · AI-Assisted Security Review

For a Microsoft Global Hackathon project, we built an interface that checked committed code for security vulnerabilities and surfaced findings directly within the Git-based workflow.

We designed developer-facing comments that explained what was happening in an understandable way. As part of the Git interface, we added actionable UI controls alongside vulnerability findings, allowing developers to apply fixes, create a new commit, and push the updated code directly from the workflow.

02 · AI-Assisted Unit Test Generation

We extended the same idea to unit testing within the Git-based development workflow. The system checked for unit test files and could generate tests when they were missing. When tests already existed, it could also generate tests based on the specific code modifications made in the change.

We designed the experience so developers could see the resulting test execution in the build pipeline, including whether the build passed and how the generated tests performed. The interface was intended to make the quality of AI-generated tests easier to evaluate rather than asking developers to simply trust the output.
